## 0. 设计理念总览

### 一句话主张

> **把「学习技能」变成「修仙证道」，把「技术成长」变成「点亮星辰」。**

玩家进入的不是一个"学习平台"，而是一片**玄夜仙穹**——每一门技能都是一位**Boss**，每一个案例都是一个**试炼副本**，每一次点亮都是一次**破境证道**。修仙体系（炼气→神魔）不只是文案包装，而是整套视觉系统、色彩系统、勋章系统与成长激励的底层叙事。

### 三个记忆点（Differentiation）

1. **八境色彩体系** —— 境界即颜色：炼气灰→筑基青→结晶蓝→具灵青碧→悟道金→羽化朱霞→登仙紫→神魔曜金。整个产品所有界面都能"一眼看出这件技能是什么段位"。
2. **功法 = Boss 卡** —— 技能详情页右侧的 Boss 环形等级盘，把"难度"可视化成一个可以挑战的敌人，而不是冷冰冰的数字。
3. **法印勋章** —— 勋章不是卡通贴纸，而是**篆书印章 + 环形纹章**，像修仙世界的道果法印，自带东方神秘感。

### 双端世界观对比

| | **玩家端 · 玄夜仙穹** | **管理端 · 琅嬛玉阁** |
|---|---|---|
| 叙事定位 | 修仙者的世界（游戏沉浸） | 仙府中枢（行政掌权） |
| 明暗 | 深色 · 星穹夜 | 浅色 · 宣纸白 |
| 主色 | 鎏金仙光 `#E7C87B` | 朱砂印 `#C2452F` |
| 气质 | 沉浸 · 探索 · 感动 | 权威 · 清爽 · 高效 |
| 隐喻 | 技能=功法 / 案例=副本 / 点亮=证道 | 爬取=灵犀巡游 / 审核=露出 / 玩家=仙籍 |

> 设计决策：管理端刻意做成**浅色宣纸质感**而非沿用深色——一方面管理是高频操作，浅色更高效护眼；另一方面形成"玩家在世界里、管理员在仙府外"的叙事反差，两端产品气质互补而非重复。

## 1. 设计系统（Design Tokens）

### 1.1 色彩系统

#### 玩家端 · 玄夜仙穹（深色）

| Token | 值 | 用途 |
|---|---|---|
| `--bg-0` | `#070B15` | 最深底色（玄夜） |
| `--bg-1` | `#0B1120` | 页面基底 |
| `--bg-2` | `#111A30` | 卡片表面 |
| `--bg-3` | `#1A2542` | 升高表面 |
| `--gold` | `#E7C87B` | 鎏金 · 主强调（CTA/点亮/等级） |
| `--gold-deep` | `#A8823C` | 鎏金深（边框/文字渐变） |
| `--cinnabar` | `#E06B5A` | 朱砂（警示/羽化系） |
| `--ink` | `#EAEEF8` | 星白正文（对比 ≈ 13:1，AAA） |
| `--ink-2` | `#9BA5C0` | 次级正文（≈ 7:1，AAA） |
| `--ink-3` | `#5E6A8C` | 弱化信息（≈ 4.6:1，AA） |

> 中性色全部带冷紫蓝 cast（chroma≈0.01），拒绝死灰；深色用「表面亮度」代替阴影表达层级。

#### 八境色彩体系（核心 Token，两端共用同一色相、按明度适配）

| 境界 | Boss Lv | 色值（深色端） | 色值（管理端） | 设计语义 |
|---|---|---|---|---|
| 炼气期 | 1–10 | `#A8AEB8` 尘银 | `#7A7F8A` | 凡尘起步 |
| 筑基期 | 11–20 | `#6EC9A8` 青玉 | `#3E8A6A` | 灵光初现 |
| 结晶期 | 21–30 | `#6FB7E8` 冰蓝 | `#3E74A8` | 凝晶成器 |
| 具灵期 | 31–40 | `#57C8D6` 碧波 | `#2E8E9E` | 万物可驭 |
| 悟道期 | 41–50 | `#E7C87B` 鎏金 | `#A8823C` | 万法皆通 |
| 羽化期 | 51–60 | `#E8826B` 朱霞 | `#B85C46` | 脱胎换骨 |
| 登仙期 | 61–70 | `#A98BE8` 紫霞 | `#6B5B95` | 俯瞰尘世 |
| 神魔期 | 71–100 | `#F6D860` 曜金 | `#C2962E` | 一念神魔 |

> 使用规则：境界色只用于 **Boss 等级徽章、技能卡顶光、境界塔、勋章、星图** —— 严格遵循 60-30-10 法则，大面积仍以玄夜基底为主，境界色作为"10%"的强调出现，避免彩虹乱飞。

#### 管理端 · 琅嬛玉阁（浅色）

| Token | 值 | 用途 |
|---|---|---|
| `--paper` | `#F3EFE4` | 宣纸底（暖灰，非纯白） |
| `--paper-3` | `#FFFDF7` | 卡片表面（玉白） |
| `--seal` | `#C2452F` | 朱砂印 · 主操作 |
| `--gold` | `#B08A3E` | 鎏金 · 次级强调 |
| `--ink` | `#26282E` | 墨色正文（≈12:1） |
| `--line` | `#E4DECD` | 墨线边框 |

### 1.2 字体系统

| 层级 | 字体 | 备注 |
|---|---|---|
| 中文标题 | `KaiTi / STKaiti / Noto Serif SC`（楷体→宋体兜底） | 仙侠书法感，境界名/大标题 |
| 英文展示 | `Unbounded`（→ Georgia/Serif 兜底） | 品牌字 `WHATS AWESOME`、数字统计、Boss Lv |
| 正文 | `PingFang SC / Microsoft YaHei / system-ui` | 清晰可读，13–15px |
| 代码 | `Cascadia Code / JetBrains Mono / Consolas` | Doc 页 Hello World |

字号阶梯（管理端数据密集型用固定 rem，玩家端 Hero 用 clamp 流式）：
`10px(铭文) → 12px(元信息) → 14px(正文) → 17px(卡题) → 22-26px(页题) → 34-72px(境界大标题)`

### 1.3 空间与形态

- 间距基模 **4px**：`4/8/12/16/24/32/48`
- 卡片圆角 **16–18px**（玩家端）/**14px**（管理端），按钮全圆角 `99px`
- 技能卡统一 2px 境界色顶光条 + 鼠标跟随光斑（`--mx/--my` radial-gradient）
- 阴影：玩家端用「光晕」而非硬阴影（`box-shadow: 0 0 20px color-mix(...)`）

## 2. 玩家端 · 页面 UX 规格

### 2.1 登录页（观星台）

- **目标**：3 秒内传递世界观 + 完成 GitCode OAuth 登录
- **布局**：星穹粒子背景 + 旋转法印 Logo（CSS 双环动画）+ 品牌字 + 一句 Slogan「入仙途 · 学万法 · 点亮属于你的技能星辰」
- **交互**：GitCode 登录按钮（白底、带 GitHub 猫 logo 的辨识感按钮）；下方实时统计条（技能/副本/玩家/今日灵讯）建立规模感
- **动效**：法印悬浮 float + 双环反旋；进入后平滑切入首页

### 2.2 仙穹首页（Whats New）

- **信息架构（自上而下）**：
  1. Hero —— 大标题「一朝入道，万象更新」（鎏金渐变大字）+ 双 CTA（挑战技能 / 探索副本）
  2. **今日灵讯** —— AI 每日爬取资讯流，左缘境界色条 + 时间戳；关联技能的资讯显示「⟶ 关联技能」跳转链接
  3. **最新技能** —— 今日新收录技能卡（复用技能卡组件）
  4. **境界天梯** —— 八层境界塔，每层显示 `Lv 区间 / 境界名 / 已点亮数`，悬浮右移 + 进度底条，点击直达宝库并预筛选
- **决策**：资讯区放在首页 Hero 之下，突出「每天都有新东西」的产品节奏

### 2.3 技能宝库（万法阁）

- **筛选三件套（全部并行可组合）**：
  - 搜索框（名称/厂商/领域/标签）
  - 排序段控：最新 / 重要性 / 难度
  - 状态段控：全部 / 已点亮 / 待挑战
  - 境界 Chips + 领域标签云（可多选交叠）
- **技能卡（功法卡）规格**：
  - 顶部：技能名 + 厂商 · 领域
  - 中部：两行简介（截断）
  - 底部：`Boss 徽章（境界色点 + 境界名 + Lv.N）` + `重要性 ★★（N/10）`
  - 已点亮：整卡金色描边 + 右上角「✦」光晕印章
  - 交互：hover 上浮 + 境界色光斑跟随鼠标；点击进详情

### 2.4 技能详情页（功法 Doc）

- **左栏 Doc 内容**（写作顺序即学习动线）：
  1. 简介 + 最新灵讯（AI 每日更新的资讯摘要）
  2. 官方入口 · 开源生态（卡片式双链接）
  3. **Hello World 入门试剑**（带复制按钮的代码块）
  4. **⭐ 灵犀提示词** —— 全页核心：一段可直接复制给任意 AI 的导师提示词（虚线金框强调，文案写明「将以下提示词交给你的 AI，让它带你入门」）
- **右栏信息卡（sticky）**：
  1. **Boss 环形等级盘** —— conic-gradient 进度环 + 中央大号 `Lv.N` + 境界名 + 突破预告（「突破后进入结晶期」）
  2. **灵犀鉴重要性** —— 进度条 + AI 判定文案（≥8 分显示「未来必备」）
  3. 功法信息表（发布方/领域/标签/等级/点亮状态）
- **CTA**：挑战 · 点亮此技能 → 打开闯关 Modal

### 2.5 试炼副本（案例）

- 案例卡 = **技能剑阵**：卡片内展示技能链（`GaussDB → LangGraph → DeepSeek FC` 带箭头串联），直观呈现"多技能组合"
- 详情页含：副本说明（灵犀 AI 生成标注）/ 剑阵列表 / **通关要求**（点亮 N 门技能 + 提交实现日志）
- 差异化：案例用**图标徽章**（⚔✎🛡📚）而非境界色条，与技能卡在形态上区分

### 2.6 个人洞府（个人主页）⭐ 全场最炫

- **洞府头部**：
  - 玩家 Avatar：鎏金渐变 + 旋转虚线法印光环
  - 道号 + GitCode ID + **Title 勋章条**（`云海拾荒者 / 八境旅人 / 三厂通晓` 等彩色 title-chip）
  - 四维统计（点亮技能/通关副本/获得勋章/连战周数）
  - **突破进度条**：`炼气→筑基` 渐变填充 + 光标点，两端标注境界刻度（视觉化成长）
- **勋章墙（法印阁）**：篆书印章式圆形勋章，境界色描边 + 光晕，未解锁灰度 + 虚线
- **点亮星图**：按境界色点亮的技能矩阵（亮=境界色光点，暗=未点亮）
- **点亮记录（修行录）**：金色节点时间线

### 2.7 闯关点亮流程（关键业务流）

四步走（Modal 内 Steps 指示器）：

```
壹 研读功法 → 贰 提交试炼 → 叁 灵犀判定 → 肆 点亮功法
```

- **通道一 · 手动提交（推荐）**：拖拽上传截图/日志/作品链接 → 灵犀 AI 裁判 5 分钟内出判定（页面明示判定规则，降低提交焦虑）
- **通道二 · MCP 直连（极客）**：展示 MCP Server 连接地址、玩家令牌、`judge_submit_skill` 工具说明 + 可复制 JSON 配置；显示「灵犀裁判 · 在线」状态
- **判定反馈**：提交后按钮进入「判定中」→ 通过后金色印章点亮 + Toast 祝贺 + Steps 推进动画

## 3. 管理端 · 页面 UX 规格

### 3.1 管理登录

- 朱砂印 Logo + 「琅嬛玉阁」+ 权限角标「仅限掌印者与书记官」（呼应业务需求：**2 个管理账号**）
- 双字段登录 + 申请权限/安全审计入口

### 3.2 总览玉鉴（Dashboard）

- **六维统计卡**：已收录技能 / 今日爬取（带 12 待审角标）/ 玩家与活跃 / 今日点亮判定 / 试炼副本 / 判定服务可用率（关键 SLO 可视化）
- **灵犀今日爬取**：实时 feed，每条带厂商色块 + 建议境界 + 忽略/收录操作
- **待露出审核**：表格化，直接「露出 / 搁置」，呼应业务「AI 爬取 → 管理员决定是否露出」
- **玩家境界分布**：八境横向分布条（炼气 41% → 神魔 0.5% 的金字塔，本身即叙事）
- **今日点亮 TOP5**

### 3.3 灵犀爬取 / 技能管理

- **灵犀爬取**：每日自动爬取队列，逐条 `收录 / 查看（进抽屉）/ 忽略`，标注来源厂商 + 建议境界 + 建议重要性
- **技能管理**：全量表格（搜索 + 状态筛选：已露出/待审核/已下架），行内编辑入口
- **编辑抽屉（关键组件）**：
  - 名称/厂商/领域表单
  - **境界选择器**：八境可视化卡片（含 Lv 区间）
  - **Boss 等级滑杆** 1–100（联动境界）
  - **重要性滑杆** 0–10（呼应业务：「总分 10 分，AI 综合评估」）
  - 标签多选 chips、露出状态、判定逻辑备注（面向 MCP 判定规则的配置入口）

### 3.4 灵讯管理

- 灵讯表格：标题 / 来源 / **关联技能**（点击跳转技能详情页）/ 发布状态（已发布/草稿）
- 「灵犀撰写」按钮 + 每日辰时自动发布节奏说明

### 3.5 玩家仙籍 / 勋章铸造

- 玩家表：道号 + GitCode、境界徽章、点亮数（进度条）、勋章缩略堆叠、最近活跃、仙籍/提醒操作
- 勋章铸造：勋章模板库（篆章预览 + 铸造条件 + 启用），呼应业务「什么样的能力匹配什么样的勋章」

## 5. 动效与氛围规范

| 动效 | 位置 | 实现 | 降级 |
|---|---|---|---|
| 星穹粒子 + 流星 | 全局背景（Canvas） | 170 粒子 + 26 流星，`requestAnimationFrame` | `prefers-reduced-motion` 时直接不渲染 |
| 仙光扫过 | 主按钮 | 白色渐变斜条 `shine` keyframes（3.2s） | 无 |
| 境界色光斑 | 技能卡 hover | `--mx/--my` 跟随鼠标 radial-gradient | 无（纯装饰） |
| 页面切换 | 全局 view | 淡入 + 上移 22px（cubic-bezier(.22,.61,.36,1)） | 过渡缩至极短 |
| Boss 环充能 | 技能详情 | 进度条 `width` 1.2s 缓动 | 无 |
| 点亮成功 | 闯关 Modal | Steps 节点逐级点亮 + 金色脉冲 + Toast | 无 |
| 抽屉滑入 | 管理端编辑 | `right: -560px → 0` 42s ease | 无 |

**性能原则**：全部动效 GPU 友好（transform/opacity 优先），Canvas 粒子数按视口自适应；`prefers-reduced-motion: reduce` 全局降级为静态（已内置 `@media` 兜底）。

## 6. 无障碍（WCAG AA）

- 正文对比度 ≥ 4.5:1（玩家端 ink/ink-2 均达 AAA；弱化 ink-3 亦 ≥ 4.6:1）
- 境界色**从不单独作为信息载体**：每个境界徽章同时带「境界名 + Lv 数字」文字
- 关键 CTA 触达目标 ≥ 44px；模态框支持 Esc/遮罩关闭
- 表单控件均带 label；状态变化（判定通过）有文字 + 颜色双重反馈
- 字体用 `rem`，支持浏览器 200% 缩放

## 7. 开发落地建议（对接既定技术栈）

### 7.1 前端（Vue 3 + Element Plus）

- **Token 迁移**：本文档全部 CSS 变量 → 写入 `design-tokens.scss`（`$realm-1..$realm-8` 映射 8 境界），Element Plus 用 `CSS Variables` 覆盖主题色（`--el-color-primary` 玩家端=鎏金、管理端=朱砂）
- **组件拆分**（与后端对象解耦对齐）：
  - `SkillCard / SkillDetail / BossRing / RealmBadge / RealmTower`（技能域）
  - `CaseCard / CaseChain`（案例域）
  - `PlayerProfile / MedalWall / LightMatrix / ProgressBar`（玩家域）
  - `JudgeModal / McpPanel / StepsIndicator`（闯关域，未来对接 MCP 判定）
- **路由**：`/login /home /skills/:id /cases/:id /profile /admin/**`（admin 独立布局，与玩家端布局拆分）
- **建议**：玩家端包一层全局 `<Starfield>` Canvas 组件；重动画组件（勋章墙）用 `v-if` 懒挂载

### 7.2 华为云承载映射（与项目经理 Agent 对齐）

| 能力 | 建议华为云产品 | 备注 |
|---|---|---|
| 后端 API | **FunctionGraph**（函数计算）| 技能/案例/玩家 CRUD 拆分函数；灵犀爬取用定时触发器（每日 06:00） |
| 数据库 | **GaussDB**（主）+ **GaussDB for Redis**（缓存/点亮计数） | 技能/案例/玩家/勋章 4 张核心表 + 点亮关系表 |
| 向量检索（Doc/资讯语义关联） | **GaussDB 向量检索** | 「资讯 ⟶ 关联技能」自动匹配、技能相似推荐 |
| 灵犀 AI（爬取/撰写/判定） | **盘古大模型 / ModelArts** + 提示词工程 | 裁判 Agent 独立函数 `judge`，输出结构化判定 JSON |
| 对象存储（截图/日志） | **OBS** | 玩家提交证明存储 + 预签名 URL |
| 静态托管 | **OBS + CDN** | 玩家端/管理端 SPA |
| MCP Server | FunctionGraph 暴露 HTTPS 端点 + 鉴权 | 对接「裁判 Agent」复用同一判定逻辑 |

### 7.3 判定逻辑对接建议（UI 侧）

- 手动提交与 MCP 通道**共享同一判定函数**，UI 只需调用 `POST /judge/{skillId}`；MCP 工具 `judge_submit_skill` 内部等价调用
- 判定结果事件流（`pending → passed / rejected`）通过 WebSocket/轮询回推 UI，Steps 指示器驱动
